# 0007. 문서를 동결·살아있는·최종으로 나누고, 숫자에 조건을 붙인다

2026-09-07 · 확정 · 문서 전반에 적용

## 맥락

1주차 보고서 제출 후 수치 세 건이 분석 결과와 어긋난 것을 발견했다.
처음에는 "문서에 숫자를 손으로 옮기면 어긋난다"로 정리했으나, 이 진단은
두 가지 다른 문제를 뭉뚱그린 것이었다.

| | 상황 | 판정 |
|---|---|---|
| **A** | 조건이 달라서 숫자가 다름 (6개 구 321,785 / 8개 구 472,782) | **둘 다 사실.** 오류 아님 |
| **B** | 조건은 같은데 옛 값이 남음 | **작성 시점에 이미 오류** |

제출본(`week-01` 태그)을 확인하니 세 건 모두 B였다.

```
| 수집 범위    | 8개 자치구 × 2006-01 ~ 2026-08 |   <- 조건: 8개 구
| 정제 후 표본 | 472,812건 |                       <- 절단 전 값
...
분석 구간을 2026-05까지로 절단한다.                 <- 절단했다고 명시
거래 해제(취소) 건 4,285건                          <- 6개 구 값
반복매매 쌍 253,921쌍                               <- 6개 구 값
```

문서가 스스로 앞뒤가 맞지 않았다. "절단했다"고 써놓고 절단 전 숫자를 적었고,
"8개 구"라 해놓고 6개 구 값을 적었다.

## 결정

### 1. 문서를 세 종류로 나눈다

| 종류 | 예 | 원칙 |
|---|---|---|
| **동결** | 주차 보고서, 발표 자료 | **그 시점의 기록.** 나중에 갱신하지 않는다 |
| **살아있는** | 백로그, README, 용어집, 제안서 | **항상 현재 상태.** 갱신 대상 |
| **최종** | 최종 보고서 | 하나의 조건으로 통일 |

동결 문서를 매번 최신 숫자로 갈아엎으면 안 된다. 그것은 역사 기록의 조작이며,
"3주차에 얼마였는데 지금은 얼마다"를 볼 수 없게 만든다.

**단, B 유형(작성 시점에 이미 틀린 값)은 동결 문서라도 정정한다.** 제출 시점의
상태는 `week-NN` 태그로 보존되고 수정은 커밋 이력에 남는다.

### 2. 숫자에는 조건을 붙인다

조건 없는 숫자는 쓰지 않는다. 조건이 붙어 있으면 나중에 값이 바뀌어도
**그 문장은 여전히 참**이므로 고칠 이유가 없다.

- 나쁨: "반복매매 쌍 253,921쌍을 확보했다"
- 좋음: "8개 자치구·2026-09-03 수집 기준 반복매매 쌍 377,289쌍"

동결 문서는 최소한 **스냅샷 시점**을 문서 어딘가에 명시한다.

### 3. 현재 값의 출처는 하나로 둔다

`output/results/*.json` 이 유일한 출처다. 문서의 숫자가 이 파일과 어긋나면
JSON 이 맞다. 분석 스크립트는 결과를 반드시 JSON 으로 직렬화한다.

### 4. 검증을 자동화한다

`scripts/check_numbers.py` 가 세 가지를 검사한다.

1. **살아있는 문서에 폐기된 값이 남아 있는가** -> 오류, 종료코드 1
2. **동결 문서에 스냅샷 표기가 있는가** -> 경고
3. 감시 대상 수치가 어느 문서에 어떤 값으로 있는가 -> 보고

현재 값은 JSON 에서 읽는다. 검증기에 하드코딩하면 같은 문제가 반복되기
때문이다. **손으로 관리하는 것은 폐기된 값 목록뿐이며 추가 전용이다** —
숫자가 바뀔 때마다 옛 값을 `WATCHED[...]["retired"]` 에 사유와 함께 적는다.

## 대안

- **모든 문서를 최신 값으로 동기화**: 동결 문서까지 갈아엎게 되어 기록이 사라진다.
- **문서에 마커를 심고 빌드 시 주입** (`472,782<!--#표본-->`): 사본이 하나가 되어
  원리적으로 어긋날 수 없다. 다만 아직 어떤 숫자가 최종본에 남을지 모르는
  단계에서 마커를 심으면 문장을 고칠 때마다 관리 부담이 된다.
  **M3(11/05, 결과 동결) 시점에 재검토한다.**

## 영향

- 주차 보고서는 이후 갱신하지 않는다. 대신 작성 시 스냅샷 시점을 반드시 적는다.
- `run_all.py --extra` 에 검증 단계를 넣어 매 실행마다 확인한다.
- 이 원칙은 [[0006-서술원칙-반사실-명시]] 와 같은 계열이다.
  거기서는 "비교 대상 없는 %를 쓰지 마라", 여기서는 "조건 없는 숫자를 쓰지 마라".
